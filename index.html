LLM models and infrastructure

How a language model works, what it takes to run one, and why it matters where it lives. Explained with one picture: a book.

Cassio Milani · 26 November 2026
/deliverance.ai · LLM models and infrastructure
The idea

An LLM or SLM is a book of numbers

LLM means large language model; SLM means small language model. Either one is a book of numbers loaded into memory. To write one word, the processor (a CPU or a GPU) reads the whole book. For the next word, it reads the whole book again.

CPU: the general-purpose processor in every computer. GPU: a processor built to do a huge number of sums at once.
LLM models

LLM parameters: how big the book is

An LLM parameter is one tiny dial that training set to the right position. Each number in the book records one dial's setting. A 20B model has 20 billion dials. A 200B model has ten times as many.

More dials: more it can know, more to store, and more to read for every word.
LLM models

Dense vs sparse: the reading race

Both must write the same 14 words. Dense reads the whole book for every word. Sparse splits its book into chapters, and a built-in index picks the 4 each word needs: about 14 times less reading.

Pick dense when you do not have much memory. Every word uses everything the model knows, so you get the best answers for the space it takes.
Pick sparse when you need fast answers. It needs a lot of memory, but it answers like a bigger model at the speed of a small one.
LLM models

Reasoning or not: thinking before answering

A reasoning model writes out its working before it answers. Each thinking word costs a full read of the book, just like an answer word, so it is slower but gets hard questions right more often.

Pick reasoning for hard, multi-step questions: planning, maths, finding the cause of a fault.
Pick no reasoning for simple jobs: summaries, lookups, chat. The answer arrives several times sooner.
LLM models

Precision: how fine each dial is

The same model, with the same number of dials, can be saved at different precision. Bits decide how finely each dial is set: with fewer bits a dial has fewer clicks, its setting is a little rounder, and the book is much thinner.

Pick more bits when every detail of the answer matters and you have plenty of memory.
Pick fewer bits when the book has to fit a smaller desk or answers must come faster. Going down to 4 bits costs only a little quality.
LLM models

Context window: how much it can read at once

The context window is the model's notepad. Your question, your documents and the conversation so far must all fit on it. What does not fit, the model cannot see.

Pick a big window for long documents, long conversations and agents that work through many steps.
Pick a small window for short questions. A fuller notepad needs more memory and more reading time.

Infrastructure

Memory size: will the book fit on the desk?

Memory is the desk. The whole book has to fit on it, with a little room to work, or the model cannot run. A CPU uses the server's main memory: a very big desk. A GPU card brings its own desk: smaller, and fixed in size.

Memory speed: how fast the pages turn

Size is not the whole story: memory also sets how fast the pages turn. A CPU server's memory turns a few pages at a time. A GPU card's memory turns many at once, so the words arrive about 20 times faster.

Memory matters more than the processor

The processor (a CPU or a GPU) is a very fast reader, but it can only read as fast as memory turns the pages. Most of the time it is waiting. Try making each part twice as fast.

Infrastructure

Unified memory: one desk for both

In most machines the CPU and the GPU each have their own desk. With unified memory they share one big desk: bigger books fit in one small machine, but the pages turn slower than on a GPU card.

Pick unified memory to run a big model on one small machine, for one person or a small team.
Pick GPU cards to serve many people at once. Their pages turn faster, and you can add more cards later.

Infrastructure

Too big for one card? Split the book

A book too big for one GPU card is cut into parts, one part per card, in one server or several. To write a word, the work is handed from card to card, like a relay. If the hand-over is slow, every word is slow.

Infrastructure

Everyone shares the same output

Everyone who asks is sharing one model. It writes 200 words a minute in total, however many people are asking. The more people at once, the fewer words each one gets.

Sovereign AI

Sovereign AI: rent the book, or own it?

With a rented AI, your questions and documents leave your building. Depending on the provider and the laws it answers to, they may be kept, used to train its model, or read by others. With your own, they never leave.

Summary

Seven things to remember

  • What a model isA book of numbers. To write one word, the processor reads the whole book.
  • How big it isMore parameters, a bigger book: it knows more, and it is slower.
  • What it can seeThe context window: your question and documents must fit in it.
  • Will it fitThe whole book must fit in memory. A GPU card's memory is fixed in size.
  • How fast it isFast memory means fast words. Memory matters more than the processor.
  • How many peopleEveryone shares the same output. More people, fewer words each.
  • Why own itYour data stays in your building, whoever made the model.
